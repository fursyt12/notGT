### What's new in 0.17.0

- **Karaoke from Spotify.** `notGT Karaoke.exe`, new in the Windows package next to the
  launcher, follows what Spotify plays on that computer, finds its synced lyrics and sends
  the line being sung to notGT. The new **Karaoke** example of the library shows it: the
  line fills left to right (word by word when the lyrics have word timing), the next one
  under it, and dots count down a pause. Existing libraries get the example once.
  - In its window type notGT's address and, if the server asks for one, a WebSocket key
    (Team tab); it can run on another computer than the server. Closing the window hides
    it in the notification area, whose menu has the same controls and **Quit**.
  - The lyrics come from LRCLIB and NetEase, and from Musixmatch with a token of your own
    account. A song's timings from every source are kept as variants: **Previous / Next**
    switch them when the one shown is out of sync, **Earlier / Later** move the text by
    100 ms, and both are remembered for the track.
  - It needs Windows 10 1809 or later. See
    [karaoke/README.md](https://github.com/fursyt12/notGT/blob/v0.17.0/karaoke/README.md).
- **Render a seamless loop.** **`Loop`** in the Render dialog renders one cycle of what
  moves on air, from where the entrance is over and without the exit, so the file plays on
  in a loop without a jump. With the loop length at 0 it is found from the animation's own
  endless animations and looping videos (up to 60 s); a back-and-forth animation keeps its
  direction. When no length that short fits them all, the dialog says which part is off at
  the seam and after how long everything does come round.
- **Render on another machine.** `npm run render` in `bundles/notGT` renders an animation of
  any notGT server (0.16.0 or newer) with that machine's browser and ffmpeg, for a server
  that cannot render by itself. It only reads from the server; nothing goes on air.
  ```
  npm run render -- --server http://192.168.1.20:9090 --user admin --password admin --list
  npm run render -- --server … --title "Lower third" --format dxv --hold 5
  npm run render -- --server … --title "Side" --format webm --loop
  ```
- **"The browser quit at start" on Windows.** A browser that hands itself over to a new
  process when it starts is now waited for, every browser found is tried in turn, and if
  the render still cannot start, the message names the browser and ends with what it logged.
