# notGT Spout

[English](README.md) · **Русский**

Библиотека **Spout** для notGT: out как отправитель Spout 2 на Windows. Это не отдельная
программа: отправитель notGT из [`../ndi`](../ndi/README_RU.md) рисует страницы out, как
и для NDI, и отдаёт их кадры этой библиотеке; лаунчер запускает этого отправителя вместе
с сервером.

Resolume, TouchDesigner, OBS с плагином Spout2 и многие другие программы на Windows
принимают и **Spout** — текстуру, общую для программ на одном компьютере, прямо на
видеокарте. В **Titles & Outs** переключатель **Spout** стоит под переключателем NDI;
включённый, он делает out отправителем Spout на том компьютере, где работает
отправитель notGT: `notGT <out>`, если в настройках не задано другое имя, со своей
частотой кадров (60 к/с, если не задана) и с прозрачностью или без.

```
страница out ─ Chromium (видеокарта) ─► текстура D3D11 ─► Resolume · TouchDesigner · OBS
```

- **На видеокарте, как есть.** С видеокартой кадр Chromium так и остаётся текстурой:
  одна отрисовка на видеокарте переносит его в текстуру, которую открывают приёмники
  Spout (с прямой альфой — так её ждут приёмники Spout; или непрозрачным). Ни копии через
  память, ни сжатия, ни сети. На процессоре загружается только изменившийся
  прямоугольник.
- **В размере out**, всегда: на одной видеокарте картинка поменьше почти ничего не
  экономит.
- **Только Windows и только на том компьютере, который принимает.** Spout не выходит за
  пределы компьютера. Лаунчер notGT запускает отправителя вместе с сервером, так что с
  пакетом для Windows делать ничего не нужно; иначе запустите отправителя на машине с
  Windows, как для NDI. Отправитель на Linux или macOS выходы Spout даже не запрашивает.
- **NDI не нужен.** Выходам Spout не нужен рантайм NDI; нужен модуль этой библиотеки
  (`native/`, он есть в пакете для Windows).
- **Spout не умеет считать приёмников**, поэтому выход Spout рисуется со своей частотой
  всё время — но только когда что-то движется: стоящий титр ничего не стоит.
- Out может уходить по NDI и по Spout одновременно. Тогда каждый рисует свой процесс
  (страница рисуется дважды), так что включайте только то, что принимают.

Отправитель следует протоколу Spout SDK (Spout 2.007): он есть в списке отправителей
Spout, у него есть описание и мьютекс доступа, и он считает кадры — приёмники, которые
спрашивают о новых кадрах, получают только новые. Два отправителя Spout с одним именем
быть не могут: второй говорит об этом под out.

## Что здесь

| Путь             | Что там                                                               |
| ---------------- | --------------------------------------------------------------------- |
| `native/core/`   | протокол Spout и отправитель на D3D11 (Rust, `notgt-spout-core`)       |
| `native/node/`   | модуль Node-API, `native/notgt-spout-native.win32-x64.node`            |
| `src/native.mjs` | загружает модуль                                                      |
| `src/sink.mjs`   | кадры одного out в одного отправителя: текстуры Chromium или картинки |
| `index.mjs`      | то, что импортирует отправитель                                       |

```bash
npm run build:native     # на Windows, с Rust: собирает модуль
```

## Тесты

```bash
cd native && cargo test --release -p notgt-spout-core    # на Windows
```

На Linux тесты идут под wine (он рисует, но не умеет делить текстуры между устройствами;
это проверяется на Windows):

```bash
cd native && cargo build --release --target x86_64-pc-windows-gnu -p notgt-spout-core --tests
WINEPREFIX=/tmp/wine-spout WINE_D3D_CONFIG=renderer=gl xvfb-run -a wine \
  target/x86_64-pc-windows-gnu/release/deps/sender-*.exe --test-threads=1
```
